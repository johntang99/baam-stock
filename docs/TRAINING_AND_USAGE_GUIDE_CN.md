# 训练与使用指南（baam-stock）

**版本** `guide-cn-0.1` · 2026-11-26 · 对应 plan-0.7 / contract-0.7 / phases-0.7 与原型
本系统只用于研究与验证，不构成交易信号或投资建议。文中所有数字都是虚构示例。

本指南分两部分：

- **第一部分**写给研究员和审核人：模型怎样训练、验证、做影子测试、审批上线、回滚，以及怎样用"预测与实际"对照持续改进。
- **第二部分**写给所有使用者：每天怎样用、怎样读数字、什么时候可以相信预测、怎样补充信息、怎样复盘。

文中的 D-xx 指 `BUILDING_MASTER_PLAN.md` 第 9 节的决策表，AC-xx 指 `DEVELOPMENT_PHASES.md` 的验收用例，DC 指 `DATA_CONTRACT.md`。

# 第一部分 · 训练与改进模型

## 1. 先记住三条原则

1. **只用当时能看到的数据。** 训练、回放、评估都只读取 `available_at ≤ T` 的数据，读到"未来"会直接报错（AC-16）。
2. **一切都是新版本。** 数据快照、模型、校准、阈值都有版本号。已发布的预测和结算永远不改。
3. **上线前必须过两关。** 第一关是留出期的历史检验，第二关是实时影子测试。两关都要按同一套门槛判断（D-21），再由审核人批准。没有"看到几次结果就手动调一下"这条路。

## 2. 角色与页面

| 角色 | 主要做什么 | 主要页面 |
|---|---|---|
| `researcher` 研究员 | 建数据快照、发起训练、看指标、比较参数、发起影子测试 | 研发后台：训练任务、数据快照、模型参数对比、验证总览、预测对照、影子测试 |
| `reviewer` 审核人 | 看门槛结果、批准或驳回、执行回滚 | 研发后台：发布审批 |
| `admin` 管理员 | 门槛配置、新公司接入的豁免、权限 | 运营页面 + 后台 |

## 3. 模型的生命周期

```
数据快照 → 训练任务 → 候选模型 candidate → 影子 shadow → 待审批 pending_approval → 上线 live → 退役 retired
                                     ↘ 驳回 rejected                     ↘ 回滚 rolled_back
```

训练任务的状态依次为：`queued → building_dataset → training → calibrating → evaluating → completed`，任一步都可能 `failed`（DC §5）。

**部署单位是"目标"。** `regular_60m`（60 分钟方向）、`regular_60m_move`（60 分钟预期波动）、`regular_to_close`（至收盘）、`next_regular_session`（下一时段）各自独立训练、独立上线。

## 4. 第 1 步：建数据快照（training_dataset_versions）

每次训练都从一个**冻结的数据快照**开始，不直接读线上表。

| 项 | 规则 | 依据 |
|---|---|---|
| 样本来源 | 已结算的预测时点，以固定时刻表的槽位为主（08:30、10:00、11:30、13:00、14:30、16:30 ET）；事件触发样本单独分组 | D-43、D-23 |
| 样本池 | 半导体同行 12 只（不只首批 4 只），从 2021-01 到最近一个已结算日 | D-20 |
| 切分 | 按时间分为训练 → 校准 → 验证 → 留出；每两段之间至少隔 1 个完整交易日；同一事件簇、同一宏观冲击放在同一段 | D-19 |
| 排除 | 无法结算（停牌、无同步报价、公司行为比例未知）的样本不进标签，但计入排除统计 | AC-15、D-40 |
| 特征 | `fs-0.2`：时段与日历、QQQ/SPY/VIX 代理、篮子领先滞后、波动状态，以及事件特征 | D-31 |

**操作**：研发后台 → 数据快照 → 新建。建好后用"快照对比"查看与上一版相比新增、删除、更正和过滤了多少条（AC-16 的数据部分，Phase 3 的 3.01）。如果更正很多，先查原因，再训练。

## 5. 第 2 步：训练

### 5.1 每周检查（D-22）

每周一 06:00 ET 自动检查上周新增的已结算样本。数量足够时，自动建新快照并发起训练（`trigger = scheduled_weekly`）。另外两种触发方式是手动（`manual`）和漂移告警（`drift`）。

### 5.2 训练什么

| 模型 | 用途 | 说明 |
|---|---|---|
| 历史频率、恒判平盘、动量延续 | **参照**，不上线 | 用来计算 BSS（Brier Skill Score，相对参照的改善比例），回答"比瞎猜好多少" |
| `market_logit` 行情基线 | 当前线上模型 | L2 正则多项逻辑回归，约 20 个行情特征（D-24） |
| `market_event_logit` 事件增强 | 候选 | 在基线上加事件特征；只有某个事件子类通过验证后，才对该子类放行 |
| GBDT 树模型 | 对照 | 检查非线性有没有带来额外收益 |
| HAR 波动基线 + 分位数模型 | `regular_60m_move` | 预测 \|相对收益\| 的 p50/p80/p90 |

**三层参数**（行业与公司参数消融）：

1. 市场层：所有股票共享。
2. 行业层：半导体共用的偏移。
3. 公司层：每家公司的偏移，带收缩。

新公司一开始只用前两层（`market_sector_only`）。公司层只有在留出期和影子测试中都改善时才启用（D-36、AC-21）。

### 5.3 校准

模型输出的概率要再经过一次校准（isotonic 或 Platt），校准用独立的"校准段"数据。校准有自己的版本号 `calibration_version`，所以只改校准也算新版本，同样要走影子测试。

### 5.4 训练后先看这些指标（训练任务页）

| 指标 | 意思 | 怎样算"好" |
|---|---|---|
| Brier | 三分类概率误差，越小越好 | 低于参照 |
| BSS（对历史频率、恒平盘、动量延续） | 相对参照的改善比例 | > 0，且分块 bootstrap 的 95% CI 下界 > 0 |
| 命中率 | 概率最高的类别是否发生 | 只作参考，不作上线依据 |
| ECE / 校准曲线 | 说 40% 的事是否约 40% 发生 | 曲线贴近对角线 |
| 覆盖率 | 发布数 ÷ 合格时点数 | 不能为了好成绩大量弃预测 |
| pinball loss、区间覆盖率、区间宽度 | 预期波动目标 | 80% 区间实测覆盖在 77–83%，且宽度不比 HAR 基线宽太多 |
| `n_effective` | 按交易日计的有效样本数 | 太小就不要下结论 |

**为什么用分块 bootstrap**：同一天的样本高度相关。按交易日整块重采样（2,000 次），才不会把一天的行情当成很多个独立证据（D-30）。

## 6. 第 3 步：同批对照（验证总览）

候选模型必须和线上模型**在同一批样本上**比较，不能各自挑自己发布了的样本。

- **共同覆盖**：只在两者都发布了预测的时点上比较 Brier。
- **覆盖率下降要单独看**：S3 §8.4 的判例（AC-19）中，200 个合格时点，线上发布 180 条，候选只发布 100 条。候选在自己那 100 条上成绩更好也不算通过，因为覆盖率下降了 40%，超过 10pp 的上限。
- **分组拆解**：按证券、槽位、行情状态（平静/波动）、有无新闻分别看。不能出现"总体变好、某个关键分组明显变差"（D-21：关键分组退化 ≤ 0.005 Brier）。

## 7. 第 4 步：影子测试（逐步）

影子测试就是**让候选模型在真实环境里同时运行，但不对用户显示**，用实时数据证明它的成绩不是历史上碰巧好。

| 步骤 | 做什么 | 系统会自动做什么 |
|---|---|---|
| ① 发起 | 后台 → 影子测试 → 选择候选模型与目标 | 模型状态 `candidate → shadow` |
| ② 并行运行 | 不需要操作 | 每个槽位，候选和线上模型使用**同一快照、同一起算报价**各出一条预测。候选预测锁定后不可见，窗口结束前不参与任何评分（AC-20） |
| ③ 每日查看 | 看每日对比曲线：Brier 差、覆盖率、校准 | 每天结算后更新 |
| ④ 满期 | 至少 20 个交易日（D-21），期间不要改模型 | 未满 20 天，"提交审批"按钮不可用 |
| ⑤ 判定 | 后台给出门槛结果 `pass` 或 `fail`，并列出未通过的条件 | 用 `gate_config` 自动计算，不在代码里硬编码 |
| ⑥ 提交审批 | 通过后提交 | 状态 `shadow → pending_approval` |

**影子期间要注意**：

- 如果中途发现数据问题（例如来源延迟、公司行为未入库），先修数据。修完后这段影子期作废，重新计 20 天，不能"修完接着算"。
- 影子期间出现大行情（例如政策突发）是好事，正好检验模型。但要在分组里单独看这一天，避免一天主导全部结论。

## 8. 第 5 步：审批、上线与回滚

**审批**（reviewer）：在发布审批页查看门槛结果、分组拆解、校准曲线、覆盖率，然后选择批准或驳回。审批记录会写明是谁、什么时间、依据哪个 `gate_config` 版本。

**上线**：新版本从下一个槽位开始生效。已经发布的预测仍然引用原来的 `model_version_id`，不会被改写（AC-22）。

**回滚**：上线后如果出现退化（漂移告警、`gate_regression`），审核人一键回滚到上一个 `live` 版本，并开一次训练复盘。回滚同样留痕。

**内部可见层级**（D-33）：本系统仅限内部团队使用，不对外开放。上线 ≠ 日常界面可见。日常使用界面能看到什么由 `audience` 另外控制（研发人员始终可看全部）：

| 层级 | 日常界面能看到 | 门槛 |
|---|---|---|
| v1 | 证据、解释、情景、预期波动 | 80% 区间实测覆盖率 77–83%；pinball 优于 HAR |
| v2 | 60 分钟方向概率，仅限通过的切片 | BSS > 0 且 CI 下界 > 0，留出与影子都满足 |
| v3 | 至收盘、下一时段、价格区间 | 每个目标同样的门槛 |

## 9. 用"预测与实际"对照持续改进（MP §7.1）

研发后台 → 预测对照：

1. **按槽位看成绩。** 例：10:00 槽位 80% 区间实测覆盖只有 71%，说明开盘后的波动被低估。
2. **看校准曲线。** 例：10:00 槽位说 45–55% 的事，实际只发生 35%，说明概率偏自信 → 重拟合校准（新 `calibration_version`）。
3. **看残差分组。** 找系统性偏差，例如某类事件后持续低估，再据此加特征或做新候选。
4. **处理大误差复盘队列。** 结算落在 p10–p90 区间外的预测会进入这里。逐条标注原因：
   - 新闻漏抓或延迟 → 修数据源；
   - 时间错位 → 修时间戳；
   - 基准问题 → 修篮子；
   - 真正的意外 → 只记录，不改模型。
5. **关注漂移告警。** 近 20 日 Brier 相对参照恶化，且 CI 不含 0 → 自动告警 → 开训练复盘。

**不要做的事**：根据当天或几天的结果手动改参数；删除"难看"的样本；把用户补充运行（`user_supplement`）或按需运行的成绩混进主评分。

## 10. LLM 提取的质量（D-32）

事件分析里的事实提取由 LLM 起草，所以它本身也要"训练和验证"：

- 保持约 300 份人工标注文档（财报、政策、8-K、新闻）作为评估集。
- 每次改提示词或换模型，都先在评估集上跑一遍（`extraction_eval_runs`）。
- 数值事实 precision ≥ 0.98、方向 F1 ≥ 0.85 才能进入特征；未达标的提示词版本会被特征构建拒绝（AC-30）。
- 大误差复盘中发现的提取错误，补充进评估集。

## 11. 新公司的训练（D-35、D-36）

运营 → 新公司接入，共 8 个阶段：

1. 代码解析
2. LLM 起草档案 + 人工审核
3. 来源与篮子配置
4. 历史回填（分钟行情 ≥ 3 年，秒级 ≥ 1 年）
5. 数据校验：合格报价率 ≥ 95%、同步成功率 ≥ 95%
6. 进入训练池（`market_sector_only`）
7. 影子 ≥ 20 个交易日
8. 审批上线

任何一项不达标，就停在 `blocked`，或降级为 `peer_only`（只作为同行样本）。

## 12. 每周例行（研究员，约 1 小时）

| 时间 | 事项 |
|---|---|
| 周一上午 | 查看周检训练结果：新快照对比、候选指标、是否需要开影子测试 |
| 周一上午 | 处理上周的大误差复盘队列，标注原因 |
| 每天收盘后 5 分钟 | 看影子测试的每日对比、漂移与数据源告警 |
| 每月 | 检查 `gate_config` 是否需要调整（只能在影子开始前调整，调整也要留版本） |

# 第二部分 · 使用系统获得最好的结果

## 13. 先认清四类信息

| 标签 | 含义 | 用法 |
|---|---|---|
| **历史行情** | 已经发生的价格 | 事实，注意看报价时间 |
| **当前解释** | 截至某个时刻，证据能说明什么 | "未解释部分"和"反向证据"要和"可能驱动"一样认真看 |
| **情景 · 未验证** | 待决事件可能的结果，不带数字 | 用来思考，不是预测 |
| **事前预测 · 已锁定** | 窗口开始前发布、不可修改的概率 | 唯一被计分的内容 |

没有"已锁定"标签的，都不是预测。

## 14. 每天的使用节奏（美东时间）

| 时间 | 系统在做什么 | 你该看什么 |
|---|---|---|
| 08:30 | 盘前展望（当日时段） | 隔夜新闻、财报、政策；② 分析与推理中的"缺口" |
| 10:00 | 第一个 60 分钟预测 | 开盘半小时的行情与解释；开盘后波动大，若"预测对照"显示 10:00 槽位误差偏大（原型示例如此），就看得保守些 |
| 11:30 | 先结算 10:00，再发新预测 | **先看"预测与实际"**：上一条落在区间内吗？再看新预测 |
| 13:00 | 同上 | 午盘是否出现新催化剂 |
| 14:30 | 60 分钟 + 至收盘预测 | 收盘前的关键时段 |
| 16:30 | 盘后展望（下一时段） | 盘后财报、政策；盘后涨跌是"已发生的行情"，不是预测命中 |

半日市只有 08:30、10:00、11:30（加至收盘）、13:30；休市日不运行。

**每次打开股票详情，按三步看**：

1. **① 信息采集**：这次查了多少条、来自哪些渠道；有没有抓取失败（失败 ≠ 没新闻）；有没有待复核的条目。
2. **② 分析与推理**：逐步看规则与引用，特别是"时间对齐"（新闻是否早于异动）和"反向检查"（多少跌幅只是跟随行业）。
3. **③ 预测**：概率、阈值、预期波动、状态。

## 15. 怎样读数字

- **三个类别**：跑赢 / 接近平盘 / 跑输，都是**相对同行篮子**（剔除自身的等权 11 只）。平盘的范围 = ±k × σ̂（例：σ̂ 0.60pp 时为 ±0.15pp），会随波动自动放宽或收窄。
- **概率**：例如"跑输 37% / 平盘 33% / 跑赢 30%"，意思是倾向跑输，但三者接近，信号很弱。短线方向本来就接近随机，**概率差距小就当作没有信号**。
- **预期波动**：例如 p80 = 0.58pp，表示 80% 的情况下，60 分钟相对篮子的涨跌幅不超过 0.58pp。这个数字比方向更可靠，适合用来判断"接下来一小时可能动多大"。
- **准确率**：看"近 20 个交易日"和"上线以来"，同时看样本数。n < 30 时只显示计数，不要下结论。命中率 40% 在三分类里不算差（随机约 33%），关键看 BSS 是否 > 0。
- **状态**：
  - 弃预测：数据不足、报价陈旧、停牌、基准不可用等。这不是故障，而是系统拒绝在条件不足时"硬猜"。
  - 无法结算：不计入命中率。
  - 已过期：已过有效期、等待结算。
  - 已被替代：已有更新版本，旧版灰显并可回放。

## 16. 什么时候可以更相信一条预测

这些条件**越多同时成立**，越值得参考：

- 显示层级是 `validated_public`（目标已通过门槛），而不是"模型验证中"。
- 该槽位、该证券在"预测对照"中近期校准良好，区间覆盖接近 80%。
- 数据质量"正常"，运行状态"完成"，快照未过期。
- 解释状态是"解释充分"，推理链里没有关键缺口。
- 有原始来源确认的新证据，而不是只有媒体报道或未证实信息。
- 概率最高的类别明显高于其余两类。

**应该更谨慎的情况**：

- 数据"部分缺失"或"陈旧"。
- 某个新闻源超时。
- 有待人工复核的条目。
- 事件增强模型未对该事件子类验证（只放行行情基线）。
- 重大事件刚发生 5 分钟内，证据还在核验。
- 半日市或指数调仓日。

## 17. 补充你认为重要的信息

在 ① 信息采集 页点"＋ 添加信息"（D-47、D-48）：

1. 提交**链接**最好，其次是文件，最后才是纯文本。原始来源（SEC、公司 IR、监管原文）比媒体转述更有用。
2. 可以选择类别，也可以交给系统，系统可能会追加类别。
3. 写一句"为什么重要"，方便复核。
4. 等核验结果出来：
   - **已核实 · 原始来源**：会作为证据参与分析。
   - **仅媒体来源**：会参与，但不能单独当作事实。
   - **无法核实**：只列为"用户提供，未证实"，不进入模型。
   - **重复**：系统已经有了，无需重跑。
   - **受限**：疑似未公开材料，不能使用，转合规。
5. 点"**继续分析 →**"：系统在本次运行基础上做增量补充，并排显示"补充前 / 补充后"。

补充运行的预测**单独计分**，不改变槽位预测，也不会提高你看到的准确率。它的价值在于"这条信息会不会改变判断"，而不是刷成绩。

**请不要提交**来源不明的内部材料、付费内容全文，或你无权分享的信息。

## 18. 复盘：用记录提高你自己的判断

- **预测回放**：任选一条已结算预测，逐步看锁定输入 → 起算报价 → 实际行情 → 结算理由。重点看"当时知道什么"，而不是"后来知道什么"。
- **每周一次**：在股票详情的"预测与实际"中回看本周各槽位，找出你和模型都没看懂的时段。
- **发现系统漏采或解释有误**：用"添加信息"补充，或在复盘队列中标注（研究员）。这些都会进入下一轮训练（第 9 节）。

## 19. 常见误区

| 误区 | 正确理解 |
|---|---|
| "概率 40% 跑赢，就应该买" | 这是相对篮子的短线概率，不是投资建议；40% 在三分类中只是弱倾向 |
| "盘后涨了 8%，预测命中了" | 盘后行情是已发生的事实；只有窗口开始前锁定的预测才计分 |
| "相对篮子跌 1.6pp，所以是这条新闻导致的" | 相对收益只是描述；要看推理链的时间对齐和反向检查 |
| "弃预测太多，系统不好用" | 弃预测是条件不足时的诚实选择；覆盖率另行统计，不能靠弃预测刷成绩 |
| "多补充几条信息，准确率就会更高" | 补充运行单独计分；准确率只看槽位预测 |
| "这周模型连错几次，应该马上调参" | 短期结果噪声很大；改进走每周复盘 → 候选 → 影子 → 审批 |
