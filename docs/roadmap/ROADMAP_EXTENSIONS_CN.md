# 后续扩展路线图：Phase 5–7（附加文档）

**版本** `roadmap-0.1` · 2026-11-26 · 依附于 plan-0.7 / contract-0.7 / phases-0.7
**状态：规划中，尚未进入开发。** 本文档不修改 `DATA_CONTRACT.md`，也不修改 Phase 0–4 的任何内容。当前正在进行的 Phase 1 编码照常推进。

**使用范围：仅限内部团队，使用自有资金，不对外开放。** 本系统不对第三方提供信号、建议或代客交易。

---

## 0. 三条新方向的位置

```
Phase 0–3（进行中，短线研究与预测）→ Phase 4（至收盘、下一时段、更多事件子类）
                                     ↓（各自的进入门槛）
                    Phase 5 中长期预测 → Phase 6 买卖信号 → Phase 7 系统执行交易
```

三个新阶段**都放在 Phase 3 之后**，并且按顺序进行。原因：

1. 信号必须建立在**已经验证过**的预测之上。
2. 交易必须建立在**经过回测和模拟盘验证**的信号之上。

任何一步的门槛不过，就停在上一步，不跳级。

| 阶段 | 一句话 | 进入门槛（摘要） | 粗估 |
|---|---|---|---|
| Phase 5 | 1–5 个交易日与约 20 个交易日的相对表现预测 | Phase 3 完成；短线模型上线且连续 60 个交易日无回滚 | 6–8 周 |
| Phase 6 | 带入场条件、仓位、止损、退出规则的买卖信号 | 至少一个预测目标通过门槛；含成本回测 ≥ 6 个月；模拟盘 ≥ 3 个月 | 8–10 周 + 3 个月模拟盘 |
| Phase 7 | 自有资金的系统执行：提醒 → 人工确认 → 小额自动 | 信号通过 Phase 6 门槛；风控与"一键停止"演练通过；法律、税务、券商规则确认 | 8–12 周，分 3 步，每步观察期 ≥ 1 个月 |

估算为粗估，是在 Phase 0–3 约 242 人日之外另加的工作量。进入每个阶段前，按当时的实际速度重新估算。

## 1. Phase 5 · 中长期预测

### 1.1 目标

在现有短线框架之外，增加更长周期的**相对篮子表现**预测。这一阶段也吸收原规格 S1 的"1–5 个交易日窗口"（原放在 Phase 4+）。

| 新目标 `target_id` | 窗口 | 起算 / 结算 | 类别 |
|---|---|---|---|
| `close_1d` | 下 1 个交易日收盘 | 发布后下一个官方收盘价 → 再下一个官方收盘价 | 跑赢 / 平盘 / 跑输（阈值按 σ̂ 缩放，同 D-09） |
| `close_5d` | 5 个交易日 | 官方收盘价 → 第 5 个交易日官方收盘价 | 同上 + 预期波动分位数 |
| `close_20d` | 约 1 个月（20 个交易日） | 同上 | 同上 |

### 1.2 进入门槛

- Phase 3 完成：影子测试、审批、回滚流程都跑过真实案例。
- 至少一个短线目标处于 `live`，并且连续 60 个交易日无回滚。
- 日线历史 ≥ 10 年，并且公司行为（拆股、分红）完整。

### 1.3 新数据

| 数据 | 用途 | 来源方向（未验证） |
|---|---|---|
| 日线行情（含官方收盘价、复权因子） | 标签与特征 | 现有行情供应商的日线接口 |
| 基本面时点快照（营收、毛利率、指引） | 中期特征 | SEC XBRL（免费）+ 公司公告 |
| 预期修正历史 | 中期最重要的特征之一 | 共识供应商（D-16，待选） |
| 估值时点数据 | 背景与特征 | 待选 |
| 期权隐含波动 | 预期波动特征 | 来源验证后（AC-51） |
| 宏观首发值 | 宏观敏感度 | ALFRED（已在 contract-0.4） |

### 1.4 评估的特殊点

- **窗口重叠**：每天发布一条 5 日预测，相邻样本有 4 天重叠。评估时只用不重叠的样本作主评分，或者按周、按月整块 bootstrap。
- **样本少**：20 日目标每年只有约 12 个独立样本。门槛要求的样本数要按独立样本计，达不到就只在内部展示。
- **门槛**：沿用 D-21 的结构（BSS > 0 且 CI 下界 > 0，覆盖率不降，关键分组不退化），留出 ≥ 2 年，影子 ≥ 3 个月。

### 1.5 新增表（以后的追加迁移，不改现有表）

- `daily_bars`：日线、官方收盘价、复权因子。
- `fundamental_snapshots`：基本面时点快照，带 `available_at`。
- `valuation_snapshots`：估值时点快照，带 `available_at`。
- `prediction_targets`：新增 `close_1d`、`close_5d`、`close_20d` 三行。`target_id` 枚举只追加新值。
- `forecast_schedules`：新增一个版本 `sched-0.2`，加入"每日收盘后 16:30 发布中期预测"的槽位。旧版本 `sched-0.1` 保持不变。

### 1.6 模块边界

- 新代码放在 `services/py/sr/horizon/`（中期特征与标签）。
- 复用现有的 `forecast`、`settle`、`train`、`eval`，只通过 `target_id` 和配置区分，不复制一套。
- 页面：短期预测页的目标切换中增加"中期"标签；研发后台按目标筛选即可。

## 2. Phase 6 · 买卖信号

### 2.1 目标

把**已验证的预测**变成明确、可回测的交易规则。一条信号必须写清楚六件事：

| 要素 | 例子（虚构） |
|---|---|
| 入场条件 | `close_5d` 跑赢概率 ≥ 50%，BSS 切片已通过，数据质量正常，无待决重大事件 |
| 方向与标的 | 做多 NVDA；可选：同时做空等额同行篮子 |
| 仓位 | 单笔 ≤ 账户 2%，按 σ̂ 反向缩放 |
| 止损 / 止盈 | 相对篮子 −1.5σ 止损；+2σ 止盈 |
| 持有期 | 最长 5 个交易日 |
| 失效条件 | 出现新的重大事件、数据质量降级、模型回滚 → 平仓或不开仓 |

### 2.2 进入门槛（全部满足）

1. 信号所依赖的预测目标处于 `live`，并且对应切片通过门槛。
2. **含成本回测 ≥ 6 个月**（建议用尽可能长的样本外数据，并按时间滚动前推验证）。成本包括：
   - 买卖价差（用历史 NBBO）；
   - 佣金与交易所费用；
   - 滑点模型；
   - 做空借券成本（如有做空）。
3. 回测结果：扣除成本后，相对"持有同行篮子"的超额收益在分块 bootstrap 下 CI 下界 > 0；最大回撤在预设上限内；换手率与容量合理。
4. **模拟盘 ≥ 3 个月**：用实时行情模拟下单与成交，结果与回测没有显著偏离。
5. 研究员与审核人共同签字（与模型审批同一流程）。

### 2.3 新增表（追加迁移）

- `signal_definitions`：版本化的信号规则（入场、仓位、止损、退出、失效条件），发布后不可修改。
- `signals`：每次触发的信号，引用当时锁定的预测 ID。
- `backtest_runs`、`backtest_trades`：回测配置、成本模型版本、逐笔结果。
- `paper_orders`、`paper_fills`、`paper_positions`：模拟盘记录。
- `signal_performance`：按日汇总的净收益、回撤、命中率与换手率。

### 2.4 模块边界

- 新包 `services/py/sr/signals/`，以及 `sr/backtest/`。
- **只读**预测与结算表，不修改它们。
- 信号的成绩与预测的成绩**分开统计**：预测好不代表信号好，反之亦然。

## 3. Phase 7 · 系统执行交易（自有资金，内部）

### 3.1 分三步走，每步观察期 ≥ 1 个月

| 步骤 | 系统做什么 | 人做什么 | 进入下一步的条件 |
|---|---|---|---|
| 7a 提醒 | 信号触发时推送提醒（含理由、仓位建议、止损位） | 自己在券商下单 | 提醒及时、内容正确，与模拟盘一致 |
| 7b 人工确认 | 生成订单草稿；人点"确认"后才发送到券商 | 逐笔确认或拒绝 | 实际成交与模拟偏差在预设范围内；无风控事故 |
| 7c 小额自动 | 在严格额度内自动下单 | 每日复核；随时可一键停止 | 长期观察；额度只能逐步、书面审批后提高 |

### 3.2 风控（在交易服务内强制执行，不依赖研究系统）

- **额度上限**：单笔金额、单只股票持仓、总敞口、每日最大亏损、每日最大下单次数。超过任何一项都拒单。
- **白名单**：只允许首批股票与指定 ETF，只在正常交易时段，不在停牌或 LULD 暂停期间下单。
- **数据前提**：行情陈旧、数据质量降级、模型回滚、漂移告警时，自动暂停新开仓。
- **一键停止（kill switch）**：
  - 人工按钮：立即撤销所有挂单，并停止新单。可选"同时平仓"。
  - 自动触发：当日亏损达到上限、连续异常拒单、券商连接中断、对账不一致。
- **对账**：每日收盘后与券商对账（订单、成交、持仓、现金），不一致就自动停止下一交易日的自动交易。
- **审计**：每一笔从信号 → 订单 → 成交的完整链路留痕，不可修改。
- **演练**：上线前和之后每季度，演练一次 kill switch 和断线恢复。

### 3.3 进入门槛

1. 信号通过 Phase 6 全部门槛。
2. 风控规则与 kill switch 在模拟环境中演练通过。
3. 已确认的外部事项（请自行或找专业人士确认，本文不构成法律或税务意见）：
   - 券商 API 的使用条款与费用；
   - 账户类型对日内交易的限制（例如美国保证金账户的 Pattern Day Trader 规则）；
   - 自有资金交易的税务处理；
   - 公司内部的授权与资金管理制度。
4. 券商的模拟账户（paper account）全流程跑通。

### 3.4 新增部分（独立服务与独立数据库 schema）

- **独立服务** `services/trader/`：和研究系统分开部署。它只能读取研究系统发布的信号，不能修改任何研究数据。
- **独立 schema** `trading`：
  - `broker_accounts`
  - `risk_limits`（版本化）
  - `trade_approvals`（7b 的人工确认记录）
  - `orders`
  - `fills`
  - `positions`
  - `kill_switch_events`
  - `reconciliations`
- **密钥隔离**：券商密钥只存在交易服务的密钥管理中，研究系统和 Claude Code 开发环境都拿不到生产密钥。
- **券商适配器接口** `BrokerAdapter`：先实现模拟版，再接真实券商。券商候选待评估，本文不做推荐。

## 4. 怎样加入规划而不打乱当前编码

1. **只加文档，不动契约。**
   - 把本文件放到仓库的 `docs/roadmap/ROADMAP_EXTENSIONS_CN.md`。
   - `DATA_CONTRACT.md` 和 Phase 0–4 的内容不改。
   - Master Plan 和 Development Phases 各只加一行指向本文件（设计包中已加）。
2. **告诉 Claude Code 现在不要动它。** 把第 5 节的短说明粘贴给 Claude Code，或者把其中一行加进 `CLAUDE.md`。
3. **契约变更以后再做，而且只追加。** 进入 Phase 5 时，契约升为新版本（例如 contract-1.0）：
   - 只新增表、新增 `target_id` 枚举值、新增时刻表版本；
   - 不改现有列，不改现有枚举的含义；
   - 迁移编号接在当时最后一个迁移之后。
   这样已有数据、已有预测和回放都不受影响。
4. **当前编码只需注意两点（几乎零成本）**：
   - 不要在通用代码里把"60 分钟"写死，窗口长度通过 `target_id` 和配置读取。现有设计本来就是这样（D-02、`window_rule`）。
   - 不要为交易预留任何代码或密钥。交易功能将来是独立服务。
5. **进入时机**：Phase 3 验收完成后，开一次评审会，按第 1.2 节的门槛决定是否启动 Phase 5。届时再把本文件转成正式的阶段文档和契约增量。

## 6. 关于"仅内部使用"

本系统定位为**内部团队使用**，不对外开放。原文档中的"精选用户 v1–v3"（MP §12、D-33）改为理解为**内部可见范围的分级**：例如未通过门槛的目标，只有研究员能看到；通过后，团队其他成员可见。契约中 `model_deployments.audience` 字段不变，只是不再有外部用户。
